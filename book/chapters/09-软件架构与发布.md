# 第 9 章 软件架构与发布

## 1. 本章导读

本章不再追问某条量子轨道是否正确，而是追问：一次计算怎样被组织成可复用、可测试、可审计的软件产品。AutoQuantum 是研究/教学原型，不是经过认证的科学计算软件；其价值在于把势能面、神经网络代理、量子动力学和报告连成一条透明流水线。PES 基础见《03 势能面》，NN 训练见《04 神经网络势能面》，二维方法见《07 二维反应动力学》，证据标准见《08 数值验证》。

## 2. 学习目标

学完本章，你应能：

1. 画出 `pes / nn / dynamics / visualization / core / cli` 分层；
2. 用 `PipelineConfig` 表达一次可复现实验；
3. 解释 `build → NN fit → dynamics → visualize` 四步与 `auto` 方法路由；
4. 说明 NN 代理面如何进入动力学，以及 RMSE 门控的边界；
5. 按项目真实记录复现 wheel 隔离验证、版本记录、标签和 GitHub Release；
6. 为新增 PES 或动力学方法列出一份验收清单。

## 3. 新手路径

先运行最小命令：

```bash
python -m pip install -r requirements.txt
python -m pip install -e .
autoquantum --version
autoquantum info
autoquantum run -s H3_2D -p eckart --no-nn -o output_quick
```

二维默认走含时波包，故输出 `report.html`、透射曲线、波包快照与 GIF。`--no-nn` 是理解编排的最短路径：它只跳过代理面拟合，剩余步骤与数据驱动模式共用。阅读顺序建议是 `autoquantum/core/engine.py`、`autoquantum/cli.py`，再看各子包；不要从绘图代码反推物理接口。

## 4. 公式与推导

### （1）分层架构与依赖方向

合理的依赖方向是

$$
\mathrm{cli}\to\mathrm{core}\to
\{\mathrm{pes},\mathrm{nn},\mathrm{dynamics}\}
\to\mathrm{visualization}.
$$

严格地说，项目文件中 `core.engine` 直接构造 `DashboardGenerator`，因此依赖不是数学意义上的 DAG；它通过构造参数和 `_results` 字典降低耦合。核心原则仍应保持：PES 不知道 NN，NN 不知道传播器，动力学只接受形如 `V(R,r)` 的可调用对象，绘图只消费结果。`DynamicsResult` 等公共容器位于 `autoquantum/core/base.py`。

### （2）配置是实验契约

`PipelineConfig` 把体系、PES、动力学方法、NN、网格、能量窗口、波包和输出集中为 dataclass。一次计算真正应记录的是完整配置，而不只是“用了 Eckart”。例如二维波包默认 `wp_n_R=192`、`wp_n_r=144`、`wp_dt=0.5`、`wp_n_steps=3000`、`wp_sigma_R=0.5`；入口振动宽度还会由 PES 的 $k_r,D,\alpha$ 计算。配置若不能从命令行完全表达，就要通过 Python API 保存序列化后的实际值。

### （3）四步流水线

`AutoPipeline.run()` 的控制流是

$$
\text{build PES}\to\text{fit NN surrogate}
\to\text{run dynamics}\to\text{visualize/report}.
$$

`_results` 既是阶段间数据总线，也是可视化输入协议。二维构建阶段生成 `pes_2d_grid`；若启用 NN，`_step_nn_fit_2d` 用 `AbInitioData.sample_function` 在同域采样；传播阶段用 `_nn_pes_2d(model)` 把 $(n,2)$ 的 NN 调用重新整理成广播式 $V(R,r)$。因此 NN 面不会在动力学域外推，代价是“网格范围与动力学范围必须同步”。

### （4）RMSE 门控的准确含义

代理面拟合报告能量与梯度误差：

$$
RMSE_V=\sqrt{\frac1n\sum_i[\hat V_i-V_i]^2},\qquad
RMSE_{\nabla V}=\sqrt{\frac1{nd}\sum_{i,j}|\partial_j\hat V_i-\partial_jV_i|^2}.
$$

`engine.py` 在 `RMSE_V > 0.02\,V_{\rm span}` 时发出“动力学结果不可靠”的**告警**，但不会自动中止。称其为门控时应注明是日志级质量门，而不是硬失败门。v0.6.0 默认二维启用力训练；CLI 的 `--nn-force-weight` 缺省按二维 1.0、一维 0.0 路由。`AbInitioData` 只是数据容器和函数采样器，不包含 ASE/PySCF 等从头算后端。

### （5）方法路由

`method="auto"` 在二维路由到 `wavepacket`，一维路由到 `stationary`。显式 `stationary` 遇到二维会先打印实验性警告，再调用 `QuantumReaction2D`；显式 `wavepacket` 则按维数进入一维或二维实现。CLI 顶层 `--pes` 默认是 Morse，但 `H3_2D` 分支会自动改用 Eckart，并把二维 Eckart 的 `energy_max` 调为 $0.05$ au。默认值存在两层：`PipelineConfig` 服务 Python API，`argparse` 默认值服务 CLI；二者不同并非必然错误，但必须在文档和测试中显式说明。

### （6）版本与发布不变量

项目当前在 `autoquantum/__init__.py` 声明 `__version__ = "0.6.0"`，`setup.py` 也写 `"0.6.0"`；CLI 从前者导入版本。运行时版本应以 `__init__.py` 为准，打包元数据由 `setup.py` 镜像，发布检查必须断言两者相等。当前实现是“双位置人工保持一致”，还不是构建时自动读取的单一版本文件；不能把纪律误写成已实现自动化。

发布不变量可写为：源码测试全绿、wheel 隔离安装后测试全绿、依赖无损坏、版本元数据一致、变更记录完整、资产散列一致。GitHub Release 是本项目实际使用的分发渠道；项目当前没有 PyPI 发布声明，也没有可调用的 ab initio 后端。

## 5. 与代码的对应

`autoquantum/core/engine.py` 的主循环只有四步：

```python
def run(self) -> Dict[str, Any]:
    self._step_build_pes()
    self._step_nn_fit()
    self._step_dynamics()
    self._step_visualize()
    return self._results
```

二维方法路由和实验性警告如下：

```python
if method == "auto":
    method = "wavepacket" if self.is_2d else "stationary"
if method == "wavepacket" and self.is_2d:
    self._step_dynamics_2d_wavepacket()
elif method == "stationary" and self.is_2d:
    logger.warning("2D 时间无关求解器为实验性")
    self._step_dynamics_2d()
```

`DashboardGenerator.generate_all()` 调用 PES、动力学、波包绘图器并生成 `report.html`。HTML 中嵌参数、能量范围、最大反应概率、末态波包反应概率及图片；GIF 生成失败会告警但不阻塞主流程。CLI 入口在 `setup.py` 注册为 `autoquantum=autoquantum.cli:main`。

## 6. 动手实验

### 实验 A：Python API 最小管线

```python
from autoquantum.core.engine import AutoPipeline, PipelineConfig
cfg = PipelineConfig(system_name="H3_2D", pes_type="eckart",
                     method="wavepacket", use_nn_fit=False,
                     wp_n_R=96, wp_n_r=64, wp_n_steps=400,
                     wp_scan_points=2, wp_save_gif=False,
                     output_dir="output_api")
pipe = AutoPipeline(cfg)
pipe.run()
print(pipe.summary())
```

完成后应存在 `output_api/report.html` 和 `transmission.png`。小网格只适合冒烟，不代表最终精度。

### 实验 B：隔离安装 wheel

```bash
python -m venv /tmp/aq-wheel
/tmp/aq-wheel/bin/python -m pip install dist/autoquantum-0.6.0-py3-none-any.whl
/tmp/aq-wheel/bin/python -m pip check
/tmp/aq-wheel/bin/autoquantum --version
/tmp/aq-wheel/bin/python -m unittest discover -s tests -v
```

最后一条要求当前源码树中的 `tests/` 可被隔离解释器访问，因为 wheel 不包含项目测试目录。

### 实验 C：核对散列

```bash
shasum -a 256 dist/autoquantum-0.6.0-py3-none-any.whl
```

项目 v0.6.0 实际遵循的顺序是：源码测试全绿 → 构建 wheel → 在全新 venv 安装 wheel、运行测试并执行 `pip check` → 更新 `CHANGELOG.md` 与 `RELEASE_VALIDATION.md` → 提交并打 `v0.6.0` 标签 → 创建 GitHub Release，上传同一 wheel，并核对资产 SHA-256。`RELEASE_VALIDATION.md` 记录全量 36 项测试、Python 3.14.5、macOS arm64，以及 wheel 隔离环境约 58 s；GitHub Release 资产也显示同一摘要。

## 7. 常见陷阱

- **把教学原型描述成认证软件**：README 明确要求定量使用前阅读功能边界。
- **误称存在从头算后端**：`AbInitioData` 不运行电子结构程序。
- **误称已发布到 PyPI**：本项目实际发布资产在 GitHub Release。
- **CLI 默认与 dataclass 默认混淆**：`nn_epochs` 分别是 300 和 500；CLI 参数会覆盖构造值。
- **输出目录硬编码**：`PipelineConfig.output_dir` 决定报告位置；忽略它会误以为图表丢失。
- **可视化失败阻塞科学结果**：GIF 路径应允许降级，但基础图和 HTML 缺失应视为发布失败。
- **只构建 wheel、不隔离安装**：本机可编辑安装会掩盖漏包、入口点或依赖声明问题。

## 8. 高手专栏

### 新增 PES / 动力学方法验收清单

- [ ] 在 `pes/` 或 `dynamics/` 中实现可广播调用，并明确单位、坐标和渐近边界；
- [ ] 从 `__init__.py` 导出公共类；CLI `choices`、帮助文本与 `info` 同步更新；
- [ ] `PipelineConfig` 给出安全默认，方法路由能区分维度与验证状态；
- [ ] 为解析值、值梯度、输入形状、幺正性或概率流写独立测试；
- [ ] 至少选一个解析势或可分离体系做基准，并做网格/$dt$/时长收敛；
- [ ] 报告 RMSE、容差、种子和参数来源，实验性功能必须显式告警；
- [ ] 端到端测试 `report.html` 与基础图，昂贵 GIF 允许降级；
- [ ] 更新 README、CHANGELOG、RELEASE_VALIDATION，再做 wheel 隔离安装。

架构下一阶段可把 `_results` 字典升级为带 schema 的结果对象，引入显式 `PESBackend`、`NNTrainer`、`DynamicsSolver` 协议，并让报告消费不可变数据类；这能防止字段拼错静默缺图。数据驱动管线还可把 RMSE 阈值、训练随机种子、梯度差分步长和数据来源写入机器可读 provenance。验证方面应让每一级 CI 都从 wheel 安装并运行公共 smoke tests；更高维模型、GPU 和新电子结构接口可继续参考《10 进阶专题》，单位换算和默认常数集中在《附录》会更安全。

## 9. 本章小结 + 自测题

AutoQuantum 的骨架是分层接口加四步编排：配置形成实验契约，PES 生成网格，NN 可选地产生代理面，动力学按方法路由，最后由 Dashboard 汇成 HTML。发布的关键不是“代码能打包”，而是源码与隔离 wheel 都通过同一组证据、版本一致、散列一致、记录完整。

1. 为什么二维 `method="auto"` 默认选择波包？
2. NN 拟合的 2% 阈值是硬阻断还是告警？
3. `AbInitioData` 能否代替 ASE/PySCF？
4. 为什么 `PipelineConfig` 与 CLI 默认值要分别测试？
5. 为什么 wheel 验证后还要从源码树运行测试？
